Relations are a powerful, declarative feature that lets you query data from multiple tables and receive it as a clean, nested JSON object. This is the ORM's high-level, "batteries-included" approach to handling joins, abstracting away the underlying SQL complexity.

Instead of flat rows, you get results that mirror your data's structure, like a user object containing an array of their posts.

## 1. Defining Relations
To use this feature, you must first define the relationships between your tables using the `relations` helper. This should be done in your `schema.ts` file, alongside your table definitions.

There are three types of relations you can define: `one`, `many`, and `manyToMany`.
- **`one(foreignTable, config)`**: Defines a **many-to-one** or **one-to-one** relationship. It signifies that the current table "belongs to" one record from the foreign table. You must specify which local and foreign columns connect the tables.
- **`many(foreignTable)`**: Defines a **one-to-many** relationship. It signifies that the current table can be associated with many records from the foreign table. This is a "back-reference" and is inferred from a `one` relation defined on the other table.
- **`manyToMany(foreignTable, config)`**: Defines a **many-to-many** relationship through a junction (pivot) table. Both tables can be associated with multiple records from each other. You must specify the junction table and the columns that link both tables.

### Example: Users and Posts
Let's expand our schema to include relations between `users` and `posts`.

```typescript
// src/lib/db/schema.ts
import { sqliteTable, text, integer, relations } from '@type32/tauri-sqlite-orm';

// ---- Tables ----
export const users = sqliteTable('users', {
  id: integer('id').primaryKey().autoincrement(),
  fullName: text('full_name').notNull(),
});

export const posts = sqliteTable('posts', {
  id: integer('id').primaryKey().autoincrement(),
  title: text('title').notNull(),
  authorId: integer('author_id').notNull().references(users, users.id),
});


// ---- Relations ----

// Define relations for the 'posts' table
export const postsRelations = relations(posts, ({ one }) => ({
  // A post has ONE author.
  // The relation is named 'author'.
  // It connects posts.authorId to users.id.
  author: one(users, {
    fields: [posts.authorId],
    references: [users.id],
  }),
}));

// Define relations for the 'users' table
export const usersRelations = relations(users, ({ many }) => ({
  // A user can have MANY posts.
  // The relation is named 'posts'.
  // The ORM will automatically find the corresponding 'one' relation on the 'posts' table.
  posts: many(posts),
}));
```

## 2. Querying with `include`
Once relations are defined, you can fetch them using the `.include()` method on a `select` query. You pass an object specifying which relations to load.

### One-to-Many (`many`) Example
Let's fetch a user and all of their posts.

```ts
const userWithPosts = await db.select(users)
  .where(eq(users._.columns.id, 1))
  .include({ posts: true }) // Request the 'posts' relation
  .get();

/*
Result Shape:
{
  id: 1,
  fullName: 'Jane Doe',
  posts: [
    { id: 101, title: 'My First Post', authorId: 1 },
    { id: 102, title: 'Another Post', authorId: 1 }
  ]
}
*/
```

### Many-to-One (`one`) Example
Now let's fetch a post and include its author.

```ts
const postWithAuthor = await db.select(posts)
  .where(eq(posts._.columns.id, 101))
  .include({ author: true }) // Request the 'author' relation
  .get();

/*
Result Shape:
{
  id: 101,
  title: 'My First Post',
  authorId: 1,
  author: {
    id: 1,
    fullName: 'Jane Doe'
  }
}
*/
```

Under the hood, `.include()` generates the necessary `LEFT JOIN` statements and then processes the flat results into these convenient nested objects for you.

## 3. Many-to-Many Relations
Many-to-many relationships require a **junction table** (also called a pivot or join table) that connects two tables. For example, students can enroll in many courses, and courses can have many students enrolled.

### Example: Students and Courses

```typescript
// src/lib/db/schema.ts
import { sqliteTable, text, integer, relations } from '@type32/tauri-sqlite-orm';

// ---- Tables ----
export const students = sqliteTable('students', {
  id: integer('id').primaryKey().autoincrement(),
  name: text('name').notNull(),
  email: text('email').notNull().unique(),
});

export const courses = sqliteTable('courses', {
  id: integer('id').primaryKey().autoincrement(),
  title: text('title').notNull(),
  description: text('description'),
});

// Junction table that connects students and courses
export const studentCourses = sqliteTable('student_courses', {
  studentId: integer('student_id').notNull().references(students, students.id),
  courseId: integer('course_id').notNull().references(courses, courses.id),
});

// ---- Relations ----

// Define relations for the 'students' table
export const studentsRelations = relations(students, ({ manyToMany }) => ({
  // A student can have MANY courses.
  courses: manyToMany(courses, {
    junctionTable: studentCourses,
    junctionFields: [studentCourses.studentId],  // Column(s) that reference this table
    junctionReferences: [studentCourses.courseId], // Column(s) that reference the foreign table
  }),
}));

// Define relations for the 'courses' table
export const coursesRelations = relations(courses, ({ manyToMany }) => ({
  // A course can have MANY students.
  students: manyToMany(students, {
    junctionTable: studentCourses,
    junctionFields: [studentCourses.courseId],  // Column(s) that reference this table
    junctionReferences: [studentCourses.studentId], // Column(s) that reference the foreign table
  }),
}));
```

### Querying Many-to-Many Relations
Query from either direction using the same `.include()` method.

```ts
// Fetch students with their enrolled courses
const studentsWithCourses = await db.select(students)
  .include({ courses: true })
  .all();

/*
Result Shape:
[
  {
    id: 1,
    name: 'Alice',
    email: 'alice@example.com',
    courses: [
      { id: 1, title: 'Math 101', description: 'Basic mathematics' },
      { id: 2, title: 'Physics 101', description: 'Introduction to physics' }
    ]
  },
  ...
]
*/

// Or fetch courses with their enrolled students
const coursesWithStudents = await db.select(courses)
  .include({ students: true })
  .all();

/*
Result Shape:
[
  {
    id: 1,
    title: 'Math 101',
    description: 'Basic mathematics',
    students: [
      { id: 1, name: 'Alice', email: 'alice@example.com' },
      { id: 2, name: 'Bob', email: 'bob@example.com' }
    ]
  },
  ...
]
*/
```

### Adding Data to Many-to-Many Relations
To create the relationships, insert records into the junction table:

```ts
// First, create students and courses
const alice = await db.insert(students)
  .values({ name: 'Alice', email: 'alice@example.com' })
  .returning()
  .get();

const math = await db.insert(courses)
  .values({ title: 'Math 101', description: 'Basic mathematics' })
  .returning()
  .get();

// Then create the relationship via the junction table
await db.insert(studentCourses)
  .values({ studentId: alice.id, courseId: math.id })
  .execute();
```

## 4. Key Points
- **Primary Keys Required**: The ORM uses primary keys to properly group and deduplicate results when loading relations.
- **Junction Table**: For many-to-many relations, always create a separate junction table to store the relationships.
- **Bidirectional Relations**: You can define relations from both sides (e.g., students → courses AND courses → students), allowing you to query from either direction.
- **Result Shape**: 
  - `one` relations return a single object (or null if not found)
  - `many` and `manyToMany` relations return an array (empty array if no related records)
- **Performance**: Relations use LEFT JOINs, so the main query will still return results even if there are no related records.
