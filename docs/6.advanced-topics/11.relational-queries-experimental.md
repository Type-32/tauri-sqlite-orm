> [!WARNING]
> This API is **experimental and opt-in**. It is implemented in `src/queries-v2.ts` and is **not** exported from the package entry (`@type32/tauri-sqlite-orm`), **not** part of the published `dist/` bundle, and its shape may change without notice. Use it only when you can import the module source directly, and expect to migrate when it is promoted to a stable public export.

The **Relational Queries** API is a Drizzle-style `db.query` surface built on top of the existing `.select().include()` machinery. It trades the imperative builder for a declarative object API: you describe `where`, `orderBy`, `with`, and filters as plain objects.

Everything here is additive — the core `orm.select()`, `.include()`, operators, and migrations are unchanged.

## 1. Setup

```ts
// Experimental import — from the source module, not the package entry.
// (Not resolvable via the published package until a subpath export is added.)
import { relationalQuery } from '../src/queries-v2' // relative to your source tree

// The same tables you pass to `new TauriORM(db, schema)`, with relations
// already attached via defineRelations().
const { query, $count } = relationalQuery(orm, { users, posts })
```

`relationalQuery(orm, tables)` returns `{ query, $count }`:

- `query.<table>.findMany(options?)` — all matching rows.
- `query.<table>.findFirst(options?)` — the first matching row (adds `LIMIT 1`), or `undefined`.
- `$count(table, filter?)` — row count with an optional filter.

## 2. Basic queries

```ts
const allUsers = await query.users.findMany()
const alice = await query.users.findFirst({ where: { name: 'Alice' } })
```

## 3. `where` (object filter)

`where` is a plain object. Column keys accept a value (equality) or an operator object; `AND` / `OR` / `NOT` / `RAW` compose.

### Equality and operators

```ts
await query.users.findMany({ where: { name: 'Alice' } })
await query.users.findMany({ where: { age: { gt: 18, lte: 65 } } })
await query.users.findMany({ where: { name: { like: 'Al%' } } })
await query.users.findMany({ where: { id: { inArray: [1, 2, 3] } } })
await query.users.findMany({ where: { age: { between: [18, 30] } } })
await query.users.findMany({ where: { deletedAt: { isNull: true } } })
```

Available operators: `eq`, `ne`, `gt`, `gte`, `lt`, `lte`, `like`, `ilike`, `inArray`, `notInArray`, `between`, `isNull`, `isNotNull`, `contains`, `startsWith`, `endsWith`.

### Composition

```ts
await query.users.findMany({
  where: {
    AND: [{ age: { gte: 18 } }, { emailVerified: true }],
    OR: [{ role: 'admin' }, { role: 'moderator' }],
    NOT: { banned: true },
  },
})
```

### Raw SQL

`RAW` receives the table's columns and returns a Kysely condition:

```ts
import { sql } from '@type32/tauri-sqlite-orm'

await query.users.findMany({
  where: { RAW: (cols) => sql`LOWER(${sql.ref(cols.name._.name)}) = 'alice'` },
})
```

## 4. `orderBy`, `limit`, `offset`

```ts
await query.users.findMany({ orderBy: { name: 'asc', createdAt: 'desc' } })
await query.users.findMany({ limit: 10 })
await query.users.findMany({ orderBy: { id: 'asc' }, limit: 10, offset: 20 })
```

`offset` may be used without `limit` (the ORM emits `LIMIT -1 OFFSET n`).

## 5. Loading relations with `with`

`with` mirrors the `.include()` shape, extended with per-relation filters:

```ts
const usersWithPosts = await query.users.findMany({
  with: { posts: true },
})
```

Each relation entry accepts:

```ts
{
  columns?: string[] | Record<string, boolean>,   // select specific columns
  with?: { ... },                                  // nested relations
  where?: object,                                  // filter the relation's rows
  orderBy?: { column: 'asc' | 'desc' },            // sort the relation's rows
  limit?: number,                                  // slice the relation's rows
  offset?: number,
}
```

```ts
const usersWithRecentPosts = await query.users.findMany({
  with: {
    posts: {
      where: { published: true },
      orderBy: { createdAt: 'desc' },
      limit: 3,
      with: { tags: true },
    },
  },
})
```

## 6. Filtering by relations

A relation key in the top-level `where` filters the **root** rows by the existence of a matching related record (compiled to a correlated `EXISTS` subquery):

```ts
// Users who have at least one published post.
await query.users.findMany({ where: { posts: { published: true } } })

// Users who have a post whose title starts with "Tauri".
await query.users.findMany({ where: { posts: { title: { like: 'Tauri%' } } } })
```

This works in any direction:

- one-to-many / many-to-one (`where: { posts: {...} }` or `where: { user: { name: 'X' } }`)
- many-to-many via `through` (`where: { tags: { name: 'javascript' } }`)
- nested (relation within relation): `where: { posts: { user: { name: 'Alice' } } }`

It composes with column filters:

```ts
await query.users.findMany({
  where: { AND: [{ age: { gt: 18 } }, { posts: { published: true } }] },
})
```

## 7. Counting

```ts
await $count(users)                            // total rows
await $count(users, { age: { gte: 18 } })      // filtered count
await $count(users, { posts: { published: true } }) // count with a relation filter
```

## 8. Limitations

- **Result typing**: `findMany`/`findFirst` return the base model type (`InferSelectModel<T>`); loaded relations are present at runtime but not reflected in the return type. Cast to a shape that includes the relations, or type them manually.
- **No `extras`** (computed columns) yet.
- **Per-relation `orderBy`/`limit`/`offset`** are applied in JavaScript after the query (all matching relation rows are fetched, then sorted/sliced) rather than via SQL window functions. Correct, but not optimal for very large relation sets.
- **Not importable from the published package** until a subpath export (e.g. `@type32/tauri-sqlite-orm/experimental`) is added.

## 9. Migrating back

Since this API is a thin layer over the existing builder, the equivalent core-API query is:

```ts
// Experimental
await query.users.findMany({ where: { posts: { published: true } }, with: { posts: true } })

// Core API equivalent (relation filtering not available)
await orm.select(users).where(/* … */).include({ posts: true }).all()
```

There is no data or schema difference — the two APIs share the same tables, relations, and migrations.
