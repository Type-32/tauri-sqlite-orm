Relations are a powerful, declarative feature that lets you query data from multiple tables and receive it as a clean, nested JSON object. This is the ORM's high-level, "batteries-included" approach to handling joins, abstracting away the underlying SQL complexity.

Instead of flat rows, you get results that mirror your data's structure, like a user object containing an array of their posts.

## 1. Defining Relations

Relations are defined in one place with `defineRelations`. It takes your schema object (all tables) and a callback that receives `r`, which gives you autocomplete over every table plus the `one`, `many`, and `through` helpers.

There are two kinds of relations:

- **`one`** (many-to-one / one-to-one): the current table belongs to one record of the foreign table.
- **`many`** (one-to-many / many-to-many): the current table has many records of the foreign table.

```typescript
// src/lib/db/schema.ts
import { sqliteTable, text, integer, defineRelations } from '@type32/tauri-sqlite-orm';

// ---- Tables ----
export const users = sqliteTable('users', {
  id: integer('id').primaryKey().autoincrement(),
  fullName: text('full_name').notNull(),
});

export const posts = sqliteTable('posts', {
  id: integer('id').primaryKey().autoincrement(),
  title: text('title').notNull(),
  authorId: integer('author_id').notNull().references(() => users._.columns.id),
});

// ---- Relations (all in one place) ----
export const schema = { users, posts };

export const relations = defineRelations(schema, (r) => ({
  posts: {
    // A post has ONE author: from = local FK, to = foreign PK.
    author: r.one.users({ from: r.posts.authorId, to: r.users.id }),
  },
  users: {
    // A user has MANY posts: from = parent PK, to = foreign FK.
    posts: r.many.posts({ from: r.users.id, to: r.posts.authorId }),
  },
}));
```

`from` and `to` each accept a single column or an array (for composite keys). You no longer need a matching `one` relation to define a `many` side.

## 2. Querying with `include`

Once relations are defined, fetch them with the `.include()` method on a `select` query. Pass an object specifying which relations to load.

### One-to-Many (`many`) Example

```ts
const userWithPosts = await db.select(users)
  .where(eq(users._.columns.id, 1))
  .include({ posts: true }) // Request the 'posts' relation
  .get();

/*
Result Shape:
{
  id: 1,
  fullName: 'Jane Doe',
  posts: [
    { id: 101, title: 'My First Post', authorId: 1 },
    { id: 102, title: 'Another Post', authorId: 1 }
  ]
}
*/
```

### Many-to-One (`one`) Example

```ts
const postWithAuthor = await db.select(posts)
  .where(eq(posts._.columns.id, 101))
  .include({ author: true }) // Request the 'author' relation
  .get();

/*
Result Shape:
{
  id: 101,
  title: 'My First Post',
  authorId: 1,
  author: {
    id: 1,
    fullName: 'Jane Doe'
  }
}
*/
```

Under the hood, `.include()` generates the necessary `LEFT JOIN` statements and then processes the flat results into these convenient nested objects for you.

## 3. Many-to-Many Relations (via `through`)

Many-to-many relationships use a **junction table** (pivot table) that connects two tables. With `through`, you can load the related records directly — no need to query and map the junction table yourself.

```typescript
import { sqliteTable, text, integer, defineRelations } from '@type32/tauri-sqlite-orm';

export const posts = sqliteTable('posts', {
  id: integer('id').primaryKey().autoincrement(),
  title: text('title').notNull(),
});

export const tags = sqliteTable('tags', {
  id: integer('id').primaryKey().autoincrement(),
  name: text('name').notNull().unique(),
});

// Junction table for posts ↔ tags
export const postTags = sqliteTable('post_tags', {
  postId: integer('post_id').notNull().references(() => posts._.columns.id),
  tagId: integer('tag_id').notNull().references(() => tags._.columns.id),
});

const schema = { posts, tags, postTags };

defineRelations(schema, (r) => ({
  posts: {
    // Direct posts -> tags through the junction table
    tags: r.many.tags({
      from: r.posts.id.through(r.postTags.postId),
      to: r.tags.id.through(r.postTags.tagId),
    }),
  },
  tags: {
    posts: r.many.posts({
      from: r.tags.id.through(r.postTags.tagId),
      to: r.posts.id.through(r.postTags.postId),
    }),
  },
}));
```

Query it directly:

```ts
const postsWithTags = await db.select(posts)
  .include({ tags: true })
  .all();

/*
Result Shape:
[
  {
    id: 1,
    title: 'My Post',
    tags: [
      { id: 1, name: 'javascript' },
      { id: 2, name: 'typescript' }
    ]
  }
]
*/
```

You can still traverse the junction explicitly (nested `with`) if you need the junction columns themselves.

### Adding Data to Many-to-Many Relations

Insert records into the junction table:

```ts
const post = await db.insert(posts)
  .values({ title: 'My Post' })
  .returningFirst();

const tag = await db.insert(tags)
  .values({ name: 'typescript' })
  .returningFirst();

await db.insert(postTags)
  .values({ postId: post!.id, tagId: tag!.id })
  .execute();
```

## 4. `optional: false` and predefined filters

- **`optional: false`** on a `one` relation makes the field required at the type level (no `| null`). Use it when you are certain the related record always exists.
- **`where`** on a relation applies a predefined filter to the joined table.

```ts
defineRelations(schema, (r) => ({
  posts: {
    author: r.one.users({ from: r.posts.authorId, to: r.users.id, optional: false }),
  },
  users: {
    publishedPosts: r.many.posts({
      from: r.users.id,
      to: r.posts.authorId,
      where: (alias) => eq(r.posts.published, true, alias),
    }),
  },
}));
```

Use `defineRelationsPart` to split large schemas into smaller parts; relations are attached to the tables via side effect.

## 5. Typing Relational Results

Use `InferRelationalSelectModel` to infer the result type of queries that use `.include()`. Index the `defineRelations` result by table name.

```ts
import { InferSelectModel, InferRelationalSelectModel } from '@type32/tauri-sqlite-orm';
import { users, relations } from '$lib/db/schema';

export type User = InferSelectModel<typeof users>;

const withPosts = { posts: true } as const;
export type UserWithPosts = InferRelationalSelectModel<
  typeof users,
  typeof relations.users,
  typeof withPosts
>;
// UserWithPosts = User & { posts: Post[] }
```

For nested includes, pass a map of table name → relations as the fourth parameter. See [Type Safety & Inference](/6.advanced-topics/6.type-safety-and-inference#inferrelationalselectmodel) for full details.

## 6. Key Points

- **Primary Keys Required**: The ORM uses primary keys to group and deduplicate results when loading relations.
- **Junction Table**: For many-to-many relations, create a separate junction table to store the relationships.
- **Bidirectional Relations**: Define relations from both sides (e.g. students → courses AND courses → students) to query from either direction.
- **Result Shape**:
  - `one` relations return a single object (or null if not found)
  - `many` relations return an array (empty array if no related records)
- **Performance**: Relations use LEFT JOINs, so the main query still returns results even with no related records.
